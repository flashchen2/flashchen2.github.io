AI大模型

一、名词介绍

1.LLM

  1. LLM（Large Language Model）：大语言模型。是强大的“知识库”和“回答引擎”
  2. 核心能力：回答问题
  3. 局限：
    1. 无法感知或改变外部环境，是一个纯粹的文本生成器
    2. 没有记忆

2.Agent

  1. Agent：智能体。Agent ≈ LLM + 工具调用
  2. 工具调用 = 代码对文件的crud、运行终端命令
    1. 脚本代码
    2. cli命令行操作
    3. 脚本MCP封装

3.MCP

  1. MCP（Model Context Protocol）：模型上下文协议，封装脚本代码。让 AI 模型能标准化地连接外部工具和数据源

  2. 使用前后对比

    1. 之前的方式：人工写脚本调用数据库/RPC/API，自己处理参数、错误、格式转换
    2. 现在的方式：把这些交互代码封装成 MCP Server，AI 模型通过 MCP 协议自动调用
    3. 优势：模型自动决策调用时间，和组合方式

  3. 完整实现方案：RPC接口 -> 制成MCP -> 转化为claw的skill

5.Function Calling：模型调用单个函数的协议，重点是参数结构化

4.Prompt

  1. Prompt：提示词。提示词就是Agent的 操作系统 和 行为准则

  2. 内容：模型角色、运行规则、可用工具说明、输入内容、输出格式

  3. 示例

5.RAG

  1. RAG （Retrieval-Augmented Generation）：检索增强生成。大模型 + 知识库 = RAG。可以减小模型幻觉、使用私有数据

  2. 流程：用户提问→检索外部知识库→把相关文档拼进 Prompt→大模型基于检索内容生成回答；

  3. 解决问题：大模型知识过时、幻觉、隐私数据无法训练的问题

  4. RAG的动态知识更新

    1. 制作文档更新、切片、向量化、索引刷新做成流水线
    2. 增量知识：记录版本、时间戳
    3. 旧知识失效

6.Transformer

  1. Transformer 模型（变压器）：核心自注意力机制（Self-Attention）能同时看到一句话里所有词之间的关系，而不是按顺序逐个看。是所有大模型的基础架构
  2. 结构：
    • Encoder（编码器）：擅长理解 → 多用于分类、语义理解
    • Decoder（解码器）：擅长生成 → 多用于写文章、对话、翻译

7.mos

  1. mos（Mean Opinion Socer）：人工评测分数的平均值么

二、其他

1.名词解释

  1. COT：思维链。展示推理步骤，提升可解释性
  2. 模型蒸馏：大模型通过知识迁移，将其能力传授给更轻量的小模型
  3. 强化学习
    1. 对比：监督学习（模仿）VS 强化学习（试错+奖励）
    2. 机制：答对-》奖励-》强化路径；答错-》惩罚-》调整策略
    3. 优势：泛化能力强，适合数学、变成等复杂推理
  4. AGI（Artificial General Intelligence）：终极目标，全能型AI。旨在拥有与人类相当的通用智能，能够理解、学习并执行任何智力任务
  5. AIGC（AI Generated Content）：AGI的“文艺细胞”，专注创作。是AGI的一个具体应用分支、负责文本、图像、音频等内容的生成
  6. few-shot = 少样本学习
  7. benchmark = 基准测试 / 对标标准，方便和别人、和历史版本横向对比。benchmark=普通样本 + 边界样本+长尾样本+对抗样本+安全样本
维度 Few-Shot Benchmark
本质 Prompt 技术 评估工具
用途 引导模型输出格式/风格 衡量模型能力
谁在用 开发者写 Prompt 时使用 研究者评测模型时使用
时机 推理阶段（Inference） 测试阶段（Evaluation）
是否固定 灵活，可自定义 固定标准，不能随意改动

  1. CLI： Command Line Interface = 终端命令行界面

  2. SSE（Server-Sent Events） ： 服务器主动推送事件，服务端向客户端的单向流式输出

    1. 典型使用场景：文字AI对话，打字机效果

  3. WebSocket：服务端和客户端的，双向、高频、实时通信设计

    1. 典型使用场景：多模态实时交互（语音对话、视频分析）

  4. LoRA = Low-Rank Adaptation（低秩适配），是一种高效微调大模型的技术。

四、Agent

1.交互执行模式 Superpowers

1.介绍

Superpowers 本质上是一套提示词工程规范，有非常严格的硬门槛（HARD-GATE）——比如字面上禁止跳过某个步骤

Superpowers 原则 agent实际行为
设计未批准禁止动手 复杂任务我会先用 Plan 模式拆解，等你确认再执行
苏格拉底式澄清 需求模糊时我会主动反问关键问题
TDD 写代码时我会提醒/生成对应测试
系统化调试 debug 时找根因而非治症状
任务列表管理 用 Todo 工具跟踪复杂任务进度

2.传统 AI 的陷阱：对抗循环，双方疲惫，效率低下

3.Superpowers 的解法：交互式确认（苏格拉底式对话）

4.关键区别：

  • ❌ 不是”用户说 → AI 做”（一次性）
  • ✅ 而是”用户说 → 反复澄清 → 共同理解 → AI 做”（迭代式）

2.记忆模式 Graphiti

1.三层架构

层级 对应人类记忆 存储内容 技术实现
热层 工作记忆 当前项目上下文、我的偏好、会话状态 内存 LRU
温层 长期记忆 设计决策、代码关系、Bug 历史 Neo4j + pgvector + SQLite
冷层 深层记忆 完整演进历史、归档数据 DuckDB (zstd 压缩)
