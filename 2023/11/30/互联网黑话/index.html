互联网黑话

一、软件测试

  1. crud：一种常见的计算机编程术语，它代表了四个基本的数据操作：创建（Create）、读取（Read）、更新（Update）和删除（Delete）

  2. beta用户：内测用户

  3. FYI：For Your Information

  4. QA：Quality Assurance的缩写，中文翻译为质量保证。在软件开发领域，QA通常指的是质量保证工程师，也称为测试工程师或测试人员。

  5. TE：test enginer，测试工程师

  6. FO：feature owner

  7. ODM：Original Design Manufacture，原始设计制造商。ODM业务模式能够为品牌厂商提供从产品研发、物料采购、生产制造到物流管控的 “一条龙” 服务。

  8. ODC：Outsourced Development Center，合作伙伴。

  9. FDE：测试功能设计师

  10. CCB：ODM漏测问题处理策略

  11. gap：差距、缺口

  12. 冒烟测试：

  13. SOP：”Standard Operating Procedure”，意思是标准操作规程，是一种详细描述特定任务或过程的文件，旨在确保在执行任务或过程时遵循一致的方法和步骤。SOP通常用于组织、公司、政府机构等组织中，以确保工作的一致性和质量

  14. TWS耳机：True Wireless Stereo耳机 - 无线耳机

  15. 回归测试：是软件测试中的一种测试方法，用于验证在进行软件修改或更新后，原有的功能是否仍然能够正常工作，确保修改或更新不会对原有的功能产生负面影响。

  16. 功耗DOU：基于设备功率的损耗，以及电池容量，计算设备可使用的天数（days-of-ues）

  17. Wiki：全称是维基百科（Wikipedia），是一种基于Web的协作软件，允许多个用户在网页上共同创作和编辑内容。Wiki的特点是开放性、易于编辑和协作，使得它成为了一种非常流行的知识共享和协作工具。

  18. SKU：是“Stock Keeping Unit”的缩写，中文意思是“库存量单位”。在零售业中，SKU通常是指一种特定的产品或商品，每个SKU都有一个唯一的编码，用于跟踪库存和销售。SKU通常包括产品的名称、颜色、尺寸、材料等信息，以便更好地管理库存和销售。

  19. 黑盒测试：将整个程序当做黑色的盒子，看不到里面做了什么事，只能通过输入输出看到测试结果

  20. 灰盒测试：常用于接口测试，不仅关注输入、输出的正确性，同时也关注程序内部的情况

  21. 白盒测试：也称为白盒测试或者驱动测试，是针对被测单元内部是如何进行工作的测试

  22. 强弱依赖：异常发生时，不影响核心业务流程、不影响系统可用性的依赖称作弱依赖，反之为强依赖

    1. 强依赖：如果商品详情页对下游依赖是强依赖，例如当下游依赖库存、优惠、物流出现故障的时候，将导致业务流程无法推进，会出现类似如下的说明，严重影响用户体验。

  23. UI / UE

    UI：（User Interface）用户界面，指的是用户与系统进行交互的界面

    UE：（User Experience）用户体验，指的是用户在使用产品或服务过程中所体验到的整体感受

  24. did：

    Web端中页面cookie内含有did，即设备id

  25. dry run：通常指的是“干运行”或“预运行”。它是一种模拟执行过程。 模拟状态下，达到触发条件后，不会实际触发，只会在监控模拟打点

  26. P99_rt：这个缩写通常代表“99%分位响应时间”，它是指在所有请求中，有99%的请求响应时间不超过这个值。在系统性能监控和分析中，P99_rt 是衡量系统高负载下性能的重要指标，尤其关注那些非常罕见但可能影响用户体验的长响应时间事件。

  27. max_rt：这个缩写代表“最大响应时间”，它是指在某一时间段内，系统处理请求所花费的最长时间。这个指标可以帮助我们了解系统在压力测试或者极端情况下可能达到的最差性能表现。

  28. avg_rt：平均相应时间

  29. 代码revert：指的是撤销某次提交（commit）所做的更改，将代码库恢复到该提交之前的状态

  30. CI：(Continuous Integration - 持续集成)

    核心思想： 开发者频繁地（通常每天多次）将代码变更集成到共享的主干分支（如 main 或 develop）

  31. CD：(Continuous Delivery - 持续交付)

    核心思想： 确保代码库（通常是主干分支）始终处于可随时、安全地部署到生产环境的状态。每次成功的 CI 构建（通过所有测试）都会自动准备好一个可部署的软件包或镜像

  33. jar包和war包

特性 Jar包 War包
用途 用于打包Java类文件、资源文件和元数据 专门用于Web应用程序部署
文件扩展名 .jar .war
内容 普通Java类、资源文件 Web应用(HTML/JSP/Servlet等)
运行方式 可直接运行或作为库使用 需要部署到Web容器

  1. IO操作（Input/Output Operation），即输入/输出操作，指的是计算机系统与外部世界或其他设备之间进行数据交换的过程，如对数据库和文件的crud

  2. ship：常用在代码审核 code review 中评审者回复被评审者常用语，指“代码评审通过”。指代码符合评审条件，可以合并进去主分支，进行后续发布

  3. component：组件

  4. utils：工具集

  5. ocr：从图片、扫描件或视频帧中提取文字，如：商品图片

  6. asr：将语音（音频流）转换为文字，如：口播稿

  7. 水平越权：一种常见的Web安全漏洞，指攻击者在同一权限级别下能够访问或操作其他用户的资源

    攻击方式 介绍 示例
    ID遍历攻击 通过修改URL或参数中的ID访问他人数据 /user/profile?id=123 → 改为id=124
    功能滥用 正常功能被用于越权操作 通过”忘记密码”功能重置他人密码
    关联数据泄露 通过一个入口获取关联的未授权数据 查看自己订单时获取到其他用户的订单信息

  8. 垂直越权：指攻击者通过某种方式从低权限账户提升至高权限账户，从而执行超出自身权限的操作。这是一种严重的安全漏洞，可能导致系统被完全控制

    攻击方式 介绍 示例
    直接访问高权限API 攻击者直接访问仅限管理员的API，如果后端未校验权限，攻击者可执行危险操作 GET /admin/deleteAllUsers
    篡改请求参数/Token 修改JWT、Cookie或请求头中的权限字段，如果后端未验证签名，攻击者可提升权限 // 原始Token（普通用户）
    { “role”: “user” }

    // 篡改后（管理员）
    { “role”: “admin” }
    功能滥用（逻辑漏洞） 通过正常功能间接获取高权限，如：
    密码重置漏洞：普通用户可通过暴力破解或逻辑缺陷重置管理员密码
    越权访问隐藏功能：某些功能在前端隐藏，但API仍可被直接调用
    会话固定攻击 攻击者诱骗管理员登录一个已知的Session ID，然后劫持会话

  9. AZ配平：在每一个AZ节点上，配置资源套餐、实例数均均相同的环境。主要为建设容灾应急策略，为后续AZ逃生打下基础

  10. PV & UV

PV（Page View，页面浏览量） UV（Unique Visitor，独立访客）
含义 用户每次打开或刷新一个页面即记录一次 PV 一定时间内（通常为 1 天）访问网站的唯一用户数，同一用户多次访问仅计 1 次
特点 重复浏览同一页面会累计 PV，反映页面内容的曝光次数 反映真实的用户规模，用于评估用户增长或活动效果
  1. OOM：内存溢出，指程序或系统中存在无法回收的内存或使用的内存过多，进而使得程序无法分配更多的内存以供程序使用。最终会造成程序停止正常运行
  2. gc：垃圾回收
  3. index ： 索引 = 下标 = 位置
  4. 网关/Nginx转发流程

  1. upstream：服务层（机器 / 集群），决定请求发给哪台服务器

  2. 契约层：多指两方业务的交互部分，制定的交互协议。如：前后端契约层 - 前端组件触发和后端请求字段交互之间的映射关系

  3. 浏览器的开发者工具：command + option + i / fn + f12

  4. Vibe Coding：氛围感编程，描述AI辅助的舒适编程方式。氛围编码是一种你完全信任人工智能的编码，甚至不需要阅读代码，只需要遵循氛围即可

  5. CLI： Command Line Interface = 终端命令行界面

  6. GUI： Graphical User Interface = 图形用户界面

  7. ER 图：Entity-Relationship Diagram，实体关系图， 是数据库设计中用来描述数据结构的图形化工具

  8. Webhook（网络钩子） 是一种基于 HTTP 的事件通知机制，可以理解为「反向 API」：不是你主动去查询，而是当某个事件发生时，服务端主动把数据推送到你提供的 URL 上。

    对比项 普通 API（轮询） Webhook（推送）
    触发方式 客户端主动请求 服务端事件触发
    实时性 低（需定时轮询） 高（事件即时推送）
    资源消耗 高（频繁请求） 低（按需触发）
    比喻 你不停打电话问”到了吗？” 快递到了 TA 主动打电话给你

    经典场景：支付结果异步通知，因为支付结果不是即时的

    用户付款 → 支付平台处理 → 支付平台回调商户 Webhook → 商户更新订单状态

  9. Client/Server模式：作为一个通用的架构思想，用于各种工程调用场景

    场景 Client（调用方） Server（提供方）
    gRPC 业务服务 gRPC服务实现
    MySQL 业务代码 MySQL数据进程

  10. filter：过滤器

  11. SDD（Spec-Driven Development）：规范驱动开发

    1. 规范驱动开发 是AI时代涌现的一种新型软件开发范式﻿。它强调在编写任何实际代码之前，必须首先编写一份详尽、精确、可执行的规范，这份规范是开发过程的唯一权威来源和主要驱动力。
    2. 业界将SDD实践划分为三个递进层面：﻿
      1. 规范优先（Spec-first），先写规范再开发
      2. 规范锚定（Spec-anchored），规范被持续保留用于后续演进和维护
      3. 规范即源码（Spec-as-source），规范成为任务的主要源文件，人类只编辑规范，永远不直接修改代码

  12. generation：生成器

  13. workflow：工作流、流水线。例多个 AI 模块之间的协作编排，例如一个 Agent 负责检索、另一个负责生成、第三个负责审核，按流程串联起来

  14. rubric：评分标准

  15. IAA（In-App Advertising）：应用内广告变现。在广告、游戏或短剧业务中，用户看广告，开发者赚广告收入

  16. IAP（In-App Purchase）：靠用户直接付费变现。比如充值买道具、付费解锁剧集

二、广告投放

英文缩写 英文全称 中文 使用场景
CPT Cost Per Time 按时间计费 竞价一般用的比较少，使用于品牌采买
CPM Cost Per Mille 每千人展示成本 CPM=总消费/曝光量*1000，品牌采买较多
CPC Cost Per Click 按点击计费
CPD Cost Per Download 按下载收费 常见于app类投放，在应用商店、积分墙、流量联盟比较常见
CPS Cost Per Sales 按销售收费 佣金常见，销售额1000，CPS3%，广告费30
CPA Cost Per Action 按行为收费 a代表很多，下载，注册，付费，按具体使用环境
oCPX Optimized Cost Per x 优化x付费（智能优化） 本质还是按照cpm付费，但是系统会自动优化点击转换率，以结算方式的选择优化
  1. mapi：MAPI（Marketing API）是一套广告投放平台功能的接口服务，客户可接入 Marketing API，将自有平台与快手广告投放平台整合打通，并且实现广告投放过程中的各项功能
  2. 泳道：实际开发测试中存在这样的场景，假如某个改坏了开播接口，一旦开播就报错，而公司内大量测试都依赖开播能力，如果是单一的环境，必须等待该 bug 修复后才能继续工作，工作效率大打折扣。因此测试环境的设计必须保证多个服务的改动互不干扰，保障主干道环境的稳定性，业界的通常做法是每个需求有单独的“需求环境”或“联调环境”，在快手，是通过泳道机制实现的，因此又叫“泳道环境”
