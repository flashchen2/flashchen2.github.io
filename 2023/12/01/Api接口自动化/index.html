api接口自动化测试

一、技术选型

层面 框架/组件 说明
测试引擎 JUnit 5 (Jupiter) @Order, @TestMethodOrder, MethodOrderer.OrderAnnotation
数据驱动 Kat 自研框架 (kat-framework) @KatDataProvider, @KatProfile, @KatDesc, @KatLevel, @KatTag
HTTP 客户端 OkHttp 4.8 + Kat 封装 KatHttpResponse, sendRequestByConfigAndBody 等封装方法
断言 Kat 自研 (KatAsserts) KatAsserts.assertJson(…).isEqualTo(…)
JSON 处理 Jackson + net.sf.json.JSONObject ObjectNode, ArrayNode, JSONObject.fromObject
环境管理 Kat 自研 (EnvUtils) EnvUtils.belowStaging() 判断环境
配置管理 Kat 自研 (BaseTest.getBizConfig) 从配置中心读取业务配置

核心是 快手自研的 KAT (Kuaishou Automated Testing) 框架，它封装了数据驱动、环境切换、配置读取、HTTP 发送、断言等能力，底层基于 JUnit 5 + OkHttp 运行

1. JUnit 5

测试运行引擎 — 负责”怎么跑测试”。

具体做的：

  • 定义测试方法：@Test 标记哪个方法是测试
  • 控制执行顺序：@Order(1) @TestMethodOrder 决定方法跑的先后
  • 生命周期管理：@BeforeEach / @AfterEach 在每个测试前后执行初始化/清理
  • 断言：assertEquals, assertTrue 等判断结果是否符合预期
  • 参数化测试：@ParameterizedTest + 数据源，让一个方法用多组数据跑多次

在你的项目里对应的就是 @Order(1)~(16)、MethodOrderer.OrderAnnotation.class 这些。

简单类比：JUnit 是”裁判”，决定谁上场、按什么顺序、怎么判胜负。

2. OkHttp

HTTP 客户端 — 负责”怎么发网络请求”。

具体做的：

  • 构建请求：创建 Request 对象（URL、method、headers、body）
  • 发送请求：同步 execute() 或异步 enqueue()
  • 处理响应：拿到 Response（status code、headers、body）
  • 连接管理：连接池、超时设置、重试、重定向
  • 拦截器：统一加 header、日志、认证等

在你的项目里，sendRequestByConfigAndBody / sendRequestByConfigAndBodyWithHeaders 底层就是 OkHttp 在发 HTTP 请求并拿到响应。

简单类比：OkHttp 是”快递员”，负责把请求送到服务器并把响应带回来。
